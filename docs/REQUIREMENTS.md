## 1. 产品愿景

打造一款**开放世界 3D 宝可梦-like 游戏**：玩家在原创地区中自由探索，收服并培养原创生物，以**实时动作战斗（宝可梦 Legends: Z-A 风格）**与野生生物、训练师、道馆馆主对战，最终成为地区冠军。

| 维度 | 决策 |
|------|------|
| 战斗风格 | Z-A 式**实时动作战斗**（竞技场自由移动 / 闪避 / 卡时机放招） |
| 探索风格 | 朱紫式**3D 开放区域**（可自由行走的大地图） |
| 道馆 | Z-A 战斗机制 **融合** 朱紫式道馆结构（连续对战 + 徽章） |
| 养成 | 收服 + 等级/经验 + 进化 + 道具/背包 |
| 昼夜 | 有昼夜循环；**夜间禁止「对战收集点数」玩法** |
| 平台 | v1 仅 Windows 单机；联机后续迭代 |
| 美术 | 程序生成占位图形 + 开源 CC0 素材（重命名避版权） |
| 范围 | 完整体验（探索 + 实时战斗 + 收服养成 + 道馆 + 剧情） |

> ⚠️ 范围极大，采用**垂直切片 + 分阶段 (P0–P7)** 推进。P1 先交付一个能跑的最小可玩 Demo（能走的世界 + 一场实时战斗 + 基础属性克制），后续按 `docs/TASKS.md` 滚动扩展。

## 2. 核心循环 (Core Loop)

```
探索大地图 ──→ 遭遇野怪 / 训练师
     │                │
     │                └──→ 实时战斗 (Z-A式)
     │                        │ 胜 ─→ 经验/掉落/可收服
     │                        │ 负 ─→ 送回宝可梦中心
     │                ┌───────┘
     ├──→ 宝可梦中心(治疗/队伍管理/存档)
     ├──→ 收服新生物 → 加入队伍/存储
     ├──→ 道馆挑战 → 徽章 → 解锁进度
     └──→ 昼夜流转 (夜间禁用对战收集点数)
```

## 3. 世界观（原创占位设定）

- **地区名**: 「星澜地区 (Stellara Region)」—— 由浮空岛屿与低地森林组成，昼夜景观差异明显。
- **生物统称**: 「灵兽 (Wispera / 单数 Wispi)」—— 取代"宝可梦"的原创称呼。
- **玩家身份**: 新晋「灵兽驭使」，目标是集齐 8 枚道馆徽章并挑战冠军。
- **核心冲突**: 地区夜间的「黯潮」现象使部分野怪狂暴，因此**夜间禁止以对战方式收集点数/收服**（设计规则，见 §9）。

> 以上为占位叙事，后续由剧情设计细化。所有名称可随时替换，不影响系统。

## 4. 3D 探索（朱紫式，P2 完整 / P1 切片）

- **玩家控制器**: `CharacterBody3D`，支持走/跑、跳跃、镜头相对移动。
- **相机**: 第三人称跟随（默认用 `phantom-camera` 插件），可旋转/缩放。
- **世界**: `Terrain3D` 可编辑地形（P2 接入）；P1 先用扁平测试场地 + 碰撞体验证控制器。
- **交互**: 草丛 → 随机野怪遭遇；NPC → 对话（P2）；宝可梦中心 → 治疗/存档（P2）。
- **HUD**: 小地图占位、当前队伍首位、时间/天气（P7 完善）。

---

## 5. 实时战斗系统（Z-A 式，P1 原型 / P3 深化）

### 5.1 核心机制
- 进入战斗后切换到**竞技场子场景**（独立场景，非大地图）。
- 玩家**实时操控己方灵兽**在竞技场内自由移动（WASD + 镜头相对）。
- **闪避**: 翻滚/冲刺带短暂无敌帧（P3 加完美闪避判定）。
- **出招**: 选择技能后进入**蓄力/前摇**，在判定窗口内放招；命中取决于距离/朝向/对方闪避。
- **招式冷却**: 每招有冷却条（P3 完整），P1 用简单冷却。
- **胜负**: 一方灵兽 HP 归零判负；可换人或投降。

### 5.2 属性克制（数据驱动）
- 原创属性示例（占位，可调整）: 炎 / 水 / 木 / 雷 / 岩 / 风 / 光 / 暗 / 械 / 灵。
- 克制倍率表存放于 `data/type_chart.json`（2× / 1× / 0.5× / 0×），战斗时实时查表。
- 实时战斗中，克制影响**伤害数值**（不因回合制而消失）。

### 5.3 数值模型（占位公式）
```
伤害 = floor( (2*Level/5 + 2) * Power * Atk/Def / 50 + 2 ) * 克制倍率 * 随机(0.85~1.0) * 时机加成
```
- 种族值: HP / 攻 / 防 / 特攻 / 特防 / 速（实时战斗中"速"影响移动速度而非出手顺序）。
- 技能: 名称 / 属性 / 威力 / PP(实时战作能量) / 命中 / 类型(物理·特殊·变化) / 状态效果。

### 5.4 状态异常（P3）
中毒(持续掉血)、麻痹(减速/偶尔定身)、睡眠(定身数秒)、灼烧(持续掉血+降攻)、冰冻(定身)。实时战中表现为持续 DOT / 控制。

### 5.5 特性（P3）
每只灵兽 1 个特性，开场或条件触发被动效果（如"炎体：灼伤免疫"）。

## 6. 收服与养成（P4）

- **收服**: 对野生灵兽造成损伤/异常后，投掷"灵球"，按 剩余HP/状态/球种 计算成功率（占位公式）。
- **等级/经验**: 击败野怪获得经验，达阈值升级，提升种族值对应的实时属性。
- **进化**: 满足条件（等级/道具/时段）触发进化，占位演出（缩放+换模）。
- **队伍/存储**: 最多 6 只出战，其余入"存储箱"；`autoload/SaveManager` 负责持久化。
- **背包/道具**: 伤药、各类灵球、状态解除剂等，数据驱动于 `data/items.json`。

---

## 7. 道馆（P5，Z-A 战斗 + 朱紫结构）

- 8 座道馆，每座对应一种属性倾向。
- 结构（朱紫式）: 进入 → 馆主连续对战（可能多只） → 胜利得徽章 → 解锁进度/新区域。
- 战斗采用 §5 的 Z-A 实时机制；馆主 AI 用 LimboAI 行为树。
- 徽章存入 `SaveManager`，作为主线进度 gate。

---

## 8. 昼夜循环（P1 基础 / 贯穿）

- 全局时钟 `autoload/DayNight` 驱动 `WorldEnvironment` 光照与天空颜色、雾。
- 周期占位为 N 分钟（如 8 分钟一天，可配置）。
- **夜间规则（硬性设计约束）**: 当处于"夜晚"阶段时，**禁止触发"对战收集点数 / 收服"入口**；若玩家尝试，弹出提示"夜晚黯潮汹涌，无法收服灵兽"。探索与常规对战不受影响。
- 该规则在 `DayNight` 与遭遇/收服逻辑中强制校验。

## 9. 技术方案与架构

### 9.1 目录结构
```
宝可梦游戏设计/
├─ addons/            # 下载的开源插件 (GDUnit4/LimboAI/Terrain3D/...)
├─ autoload/          # 全局单例: GameState, DataBus, DayNight, SaveManager
├─ core/              # 数据层: Creature, Move, TypeChart, 数值计算
├─ world/             # 探索: PlayerController, CameraRig, Terrain, Interactables
├─ battle/            # 实时战斗: Arena, Combatant, MoveExecutor, BattleFSM
├─ ui/                # HUD, 菜单, 对话, 队伍/背包界面
├─ data/              # JSON/Resource 数据: creatures, moves, type_chart, items
├─ tests/             # GDUnit4 单元测试
├─ docs/              # 需求/规划/devlog/规范 (harness 管理)
├─ harness/           # harness.py 任务与日志管理
└─ project.godot
```

### 9.2 关键设计原则
- **数据驱动**: 灵兽/技能/属性/道具全部存 `data/`，代码只读数据，便于平衡与内容填充（P6）。
- **单例 autoload**: 全局状态（时间、队伍、存档、数据表）通过 autoload 共享，场景间解耦。
- **状态机**: 战斗流程用 FSM（LimboAI 或 godot-state-charts）；探索/战斗场景切换清晰。
- **可测试**: 数值与克制逻辑用 GDUnit4 单测，不依赖渲染。
- **占位优先**: 所有美术先用 `MeshInstance`/色块/CC0 占位，系统跑通后再替换。

### 9.3 引入的开源工具（见 T004）
GDUnit4（测试）、LimboAI（AI/FSM）、Terrain3D（地形）、phantom-camera（相机）、
godot_dialogue_manager（对话）、PankuConsole（调试）、scatter（布景）、godot_datatable_plugin（数据表）。

## 10. 里程碑 / MVP 定义

**MVP（P1 交付，优先探索移动）**:
1. 朱紫式 3D 玩家可在测试场地行走 + 跟随相机 ✅ 探索骨架
2. 属性/技能/克制数据层可读、可在控制台验证克制倍率
3. 一场 Z-A 式实时战斗原型（测试竞技场，1v1，移动+闪避+放招+克制生效+击败判定）
4. 昼夜循环运行 + 夜间禁用收服规则可触发提示

**后续阶段**: P2 世界 → P3 战斗深化 → P4 养成 → P5 道馆 → P6 内容 → P7 发布。
详细任务与状态见 `docs/TASKS.md`（由 `harness/harness.py` 管理）。

- [ ] 打开项目按 F5，玩家可在场地行走、相机跟随、不穿模。
- [ ] 控制台/测试可确认 炎→木 2×、水→炎 2× 等克制关系正确。

- [ ] 切到夜晚后，尝试收服被拦截并提示。
- [ ] 全程无外部版权素材；所有名称原创。
