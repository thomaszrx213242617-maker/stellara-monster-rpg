## 1. 产品愿景

打造一款**开放世界 3D 宝可梦-like 游戏**：玩家在原创地区中自由探索，收服并培养原创生物，以**实时动作战斗（宝可梦 Legends: Z-A 风格）**与野生生物、训练师、道馆馆主对战，最终成为地区冠军。

| 维度 | 决策 |
|------|------|
| 战斗风格 | Z-A 式**实时动作战斗**（竞技场自由移动 / 闪避 / 卡时机放招） |
| 探索风格 | 朱紫式**3D 开放区域**（可自由行走的大地图） |
| 道馆 | Z-A 战斗机制 **融合** 朱紫式道馆结构（连续对战 + 徽章） |
| 养成 | 收服 + 等级/经验 + 进化 + 道具/背包 |
| 昼夜 | 有昼夜循环；**夜间禁止收服**（硬性设计约束） |
| 平台 | v1 仅 Windows 单机；联机后续迭代 |
| 美术 | 程序生成占位图形 + 开源 CC0 素材（重命名避版权） |
| 范围 | 完整体验（探索 + 实时战斗 + 收服养成 + 道馆 + 剧情） |

> ⚠️ 范围极大，采用**垂直切片 + 分阶段 (P0–P7)** 推进。P1 先交付能跑的最小可玩 Demo，后续按 `docs/TASKS.md` 滚动扩展。

## 2. 核心循环 (Core Loop)

```
探索大地图 ──→ 遭遇野怪 / 训练师
     │                │
     │                └──→ 实时战斗 (Z-A式)
     │                        │ 胜 ─→ 经验/掉落/可收服
     │                        │ 负 ─→ 送回治疗点
     │                ┌───────┘
     ├──→ 治疗点(治疗/队伍管理/存档)
     ├──→ 收服新灵兽 → 加入队伍/存储
     ├──→ 道馆挑战 → 徽章 → 解锁进度
     └──→ 昼夜流转 (夜间禁用收服)
```

## 3. 世界观（原创占位设定）

- **地区名**: 「星澜地区 (Stellara Region)」—— 由浮空岛屿与低地森林组成，昼夜景观差异明显。
- **生物统称**: 「灵兽 (Wispera / 单数 Wispi)」—— 取代"宝可梦"的原创称呼。
- **玩家身份**: 新晋「灵兽驭使」，目标是集齐 8 枚道馆徽章并挑战冠军。
- **核心冲突**: 地区夜间的「黯潮」现象使部分野怪狂暴，因此**夜间禁止收服**（设计规则，见 §8）。

> 以上为占位叙事，后续由剧情设计细化。所有名称可随时替换，不影响系统。

## 4. 3D 探索（朱紫式，P2 完整 / P1 切片）

- **玩家控制器**: `world/PlayerController.gd`（`CharacterBody3D`），支持走/跑、跳跃、镜头相对移动；移动带 `velocity_lerp` 惯性平滑；按 W 沿 **−Z**（Godot 前进方向）移动。
- **相机**: **自研第三人称跟随相机** `world/CameraRig.gd`（`Node3D` + 子 `Camera3D`，运行时 `current=true`），支持旋转/缩放、距离跟随、移动加速时 FOV 微增、行走头部位移（head bob）。
  - ⚠️ 文档历史版本曾写"默认用 phantom-camera 插件"——**该插件从未引入**，已实现为自研 `CameraRig`，此处为过时错误，已纠正。
- **世界**: 地形 P2 接入开源地形工具（候选 Terrain3D / HTerrain，见 §9.3）；P1 用代码构建的测试场地 + 碰撞体验证控制器。
- **交互**: 草丛 → 随机野怪遭遇；NPC → 对话（P2）；治疗点 → 治疗/存档（P2）。
- **HUD**: 小地图占位、当前队伍首位、时间/天气（P7 完善）。

## 5. 实时战斗系统（Z-A 式，P1 原型 / P3 深化）

### 5.1 核心机制
- 进入战斗后切换到**竞技场子场景**（独立场景，非大地图）。
- 玩家**实时操控己方灵兽**在竞技场内自由移动（WASD + 镜头相对）。
- **闪避**: 翻滚/冲刺带短暂无敌帧（P3 加完美闪避判定）。
- **出招**: 选择技能后进入**蓄力/前摇**，在判定窗口内放招；命中取决于距离/朝向/对方闪避。
- **招式冷却**: 每招有冷却条（P3 完整），P1 用简单冷却。
- **胜负**: 一方灵兽 HP 归零判负；可换人或投降。

### 5.2 属性克制（数据驱动）
- 原创属性（数据驱动，已实现 **12 种**）: 炎 / 水 / 木 / 雷 / 岩 / 风 / 光 / 暗 / 械 / 灵 / **金** / **冰**。
  - ⚠️ 历史版本写"10 种占位（缺 金/冰）"——**实际 `data/type_chart.json` 已含 12 种**，金/冰为后续补全，已纠正；完整克制与设计意图见 `GAME_DESIGN.md` §7.2。
- 克制倍率表存放于 `data/type_chart.json`（2× / 1× / 0.5× / 0×），战斗时实时查表。
- 实时战斗中，克制影响**伤害数值**（不因回合制而消失）。

### 5.3 数值模型（占位公式）
```
伤害 = floor( (2*Level/5 + 2) * Power * Atk/Def / 50 + 2 ) * 克制倍率 * 随机(0.85~1.0) * 时机加成
```
- 种族值: HP / 攻 / 防 / 特攻 / 特防 / 速（实时战斗中"速"影响移动速度而非出手顺序）。
- 技能: 名称 / 属性 / 威力 / PP(实时战作能量) / 命中 / 类型(物理·特殊·变化) / 状态效果。
- 数值计算集中在 `core/combat.gd`（自研，为数值核心；引入第三方数值工具须以"补充"而非"替代"方式接入）。

### 5.4 状态异常（P3）
中毒(持续掉血)、麻痹(减速/偶尔定身)、睡眠(定身数秒)、灼烧(持续掉血+降攻)、冰冻(定身)。实时战中表现为持续 DOT / 控制。

### 5.5 特性（P3）
每只灵兽 1 个特性，开场或条件触发被动效果（如"炎体：灼伤免疫"）。

## 6. 收服与养成（P4）

- **收服**: 对野生灵兽造成损伤/异常后，投掷"灵球"，按 剩余HP/状态/球种 计算成功率（占位公式）；**夜间受 §8 规则禁止**。
- **等级/经验**: 击败野怪获得经验，达阈值升级，提升种族值对应的实时属性。
- **进化**: 满足条件（等级/道具/时段）触发进化，占位演出（缩放+换模）。
- **队伍/存储**: 最多 6 只出战，其余入"存储箱"；`SaveManager`(单例键 `Save`) 负责持久化。
- **背包/道具**: 伤药、各类灵球、状态解除剂等，数据驱动于 `data/items.json`。

---

## 7. 道馆（P5，Z-A 战斗 + 朱紫结构）

- 8 座道馆，每座对应一种属性倾向。
- 结构（朱紫式）: 进入 → 馆主连续对战（可能多只） → 胜利得徽章 → 解锁进度/新区域。
- 战斗采用 §5 的 Z-A 实时机制；馆主 AI 用**行为树**（优先 Beehave，纯 GDScript，见 §9.3）。
- 徽章存入 `SaveManager`，作为主线进度 gate。

---

## 8. 昼夜循环（P1 基础 / 贯穿）

- 全局时钟 `DayNight`(单例键 `Clock`) 驱动 `WorldEnvironment` 光照与天空颜色、雾。
- 周期占位为 N 分钟（如 8 分钟一天，可配置）。
- **夜间规则（硬性设计约束）**: 当处于"夜晚"阶段时，**禁止触发收服入口**；若玩家尝试，弹出提示"夜晚黯潮汹涌，无法收服灵兽"。探索与常规对战不受影响。
- 该规则在 `DayNight` 与遭遇/收服逻辑中强制校验。

## 9. 技术方案与架构

### 9.1 目录结构（当前真实状态）
```
宝可梦游戏设计/
├─ addons/            # 待引入的开源插件 (当前为空, 见 §9.3 与 GODOT_TOOLS_RESEARCH.md)
├─ autoload/          # 全局单例脚本: DataBus/GameState/DayNight/SaveManager/SoundBus
├─ core/              # 数据层: Creature, Move, TypeChart, 数值计算 (combat.gd)
├─ world/             # 探索: PlayerController, CameraRig, World, Interactables
├─ battle/            # 实时战斗: Arena, Combatant, MoveExecutor, BattleFSM
├─ ui/                # HUD, 菜单, 对话, 队伍/背包界面 (TitleScreen 为主场景)
├─ data/              # JSON/Resource 数据: creatures, moves, type_chart, items
├─ test/              # 冒烟测试 (SmokeTest.gd) + 引入的单元测试
├─ docs/              # 需求/规划/devlog/规范/框架/工具调研 (harness 管理)
├─ harness/           # harness.py 任务与日志管理
├─ tools/             # 辅助脚本 (run_smoke.py 等)
└─ project.godot
```
> ⚠️ 历史版本写 `tests/`（复数）——**实际目录为 `test/`**，已纠正。

### 9.2 关键设计原则
- **数据驱动**: 灵兽/技能/属性/道具全部存 `data/`，代码只读数据，便于平衡与内容填充（P6）。
- **单例 autoload**: 全局状态（时间、队伍、存档、数据表）通过 autoload 共享，场景间解耦。
  - ⚠️ **命名约定**: `class_name` 保持语义原名（`DataBus`/`GameState`/`DayNight`/`SaveManager`/`SoundBus`），但代码里引用的**单例键**已重命名为 `Data`/`Game`/`Clock`/`Save`/`SFX`（MusicBus 已删除，共 6 个）。代码中须用键名（如 `Data.xxx`、`Clock.xxx`），不可用类名当单例。
- **状态机**: 战斗流程用 **有限状态机 (FSM)**；优先 **gd-YAFSM / SignalStateMachine**（纯 GDScript、轻量、即插即用），不接管项目、可嵌入自研 `combat.gd`。AI 决策用**行为树**（优先 Beehave，纯 GDScript）。
  - ⚠️ 历史版本写"LimboAI 或 godot-state-charts"——LimboAI 实为**行为树**框架且带 C++ 扩展依赖，并非 FSM 默认方案，已纠正。
- **可测试**: 数值与克制逻辑用单元测试，不依赖渲染；现有 `test/SmokeTest.gd` 头less 冒烟测试覆盖主场景/移动/相机；引入 GdUnit4 或 Gut（二选一）补充单元测试，二者均用独立目录、与冒烟测试不冲突。
- **占位优先**: 所有美术先用 `MeshInstance`/色块/CC0 占位，系统跑通后再替换。

### 9.3 引入的开源工具策略
- **引入前必读**: `docs/GODOT_TOOLS_RESEARCH.md`（2026-08-02 调研，含许可证/兼容/推荐优先级/排除清单）。
- **当前状态**: `addons/` 截至目前**为空**，尚未下载任何第三方工具（用户确认下载清单后再引入）。
- **优先引入项（待确认）**: Beehave(行为树AI) · gd-YAFSM/SignalStateMachine(FSM) · Addon Save(统一存档) · Dialogue Manager(轻量对话) · Inspector Extender(编辑器增强) · godot_debug_draw_3d(调试绘制) · Gut 或 GdUnit4 二选一(单元测试)。
- **已否决的历史设想**: 原文档列出的 `phantom-camera`(相机, 已自研 CameraRig, 无需引入)、`PankuConsole`、`godot_datatable_plugin` 等**不再作为默认引入项**，改以调研报告结论为准；引入 GDExtension 类须确认 Godot 4.7.1 构建可用，且引入后必须重跑 `python harness/harness.py verify` 验收闸门。

## 11. 非功能需求 (Non-Functional Requirements)

- **NFR-01 版权合规**: 一切资源/代码须满足 §0 红线；第三方仅限合规许可证。
- **NFR-02 性能**: 目标 60 FPS（Windows 单机）；移动端暂不在 v1 范围。

- **NFR-04 数据驱动**: 内容（灵兽/技能/道具/属性）与代码解耦，存 `data/`。
- **NFR-05 可维护性**: 单例键命名统一（§9.2）；新模块须有冒烟/单测覆盖。
- **NFR-06 零硬依赖陷阱**: 引入 GDExtension 工具须确认 4.7.1 构建；避免 C# 方案（与 GDScript 强冲突）。
- **NFR-07 验收自动化**: 完成度以 `harness verify` 闸门为准，不依赖人工目检。
